# 开发顺序决策：Campaign / Boss 机制优先

日期：2026-10-24  
基线：Steam M2（172abdc）  
决策：Boss Rush 与 Tower 后置；先做关卡与 Boss 机制区分。

---

## 1. 为什么后置 Boss Rush / Tower

- 两者都直接复用 Boss 定义、阶段规则和弹幕。
- 如果现在先做模式，之后每次改 Boss 都会让模式、排行榜、成就、存档一起返工。
- Boss 机制未冻结前，Tower 的 Boss 节点和 Boss Rush 的平衡没有稳定基准。
- 先冻结 Campaign/Boss，再让模式复用，返工最少。

新的顺序：

```text
Campaign / Boss 机制
→ 武器/掉落/死亡经济
→ Rank / Medal / Score
→ Boss Rush
→ Tower
→ 可选机体（Force / Resonance）
```

---

## 2. 当前死亡经济事实

代码位置：`src/game/player-state.js` 的 `hitPlayer()`。

当前规则：

- 有僚机时：消耗 1 个僚机，获得短暂无敌，不扣 HP/生命。
- 无僚机时：扣 HP，HP 归零则：
  - 生命 -1
  - HP 回满
  - `specialPower -1`（最低 1）
  - 僚机清空
  - 炸弹回 2
  - 玩家复活并短暂无敌

所以：

> 死亡时通常已经没有僚机了。  
> “死亡清空僚机”在当前规则下基本是重复惩罚。

---

## 3. 与《沙罗曼蛇》的兼容性

### 不兼容的部分

1. **死亡清空全部强化**
   - 我们已经每次死亡降 1 级武器、清空僚机、炸弹重置。
   - 再做“全清”会变成双重惩罚，容易滚雪球。

2. **Option 死亡后保留**
   - 沙罗曼蛇的 Option 不会因撞弹消失，死亡后还能回收。
   - 我们的僚机是“一次性挡弹盾”，撞弹就消耗。
   - 两者不能同时成立，否则僚机既是无限盾又是可保留资源。

3. **死亡掉落武器胶囊**
   - 死亡已经降级，再靠掉落补回来，会让死亡惩罚形同虚设；
   - 不掉，又会让死亡后体验过差。

### 兼容的部分

- **数据表驱动掉落**：可以。
- **A/B 武器胶囊选择**：可以。
- **关卡路线选择**：可以，放 1.1。
- **精英/Boss 必掉补给**：可以。
- **保底掉落（pity timer）**：可以，降低 RNG 挫败。
- **僚机回收**：不应做在死亡后，可做在“僚机挡弹被消耗”的位置，给 1.5–2 秒回收窗口。

---

## 4. 建议的死亡/掉落方案

保留当前死亡经济，不采用沙罗曼蛇全清：

```text
僚机 = 一次性挡弹盾
死亡 = 生命 -1 + 武器 -1 级 + 僚机清空 + 炸弹回 2
不再额外清空武器等级/道具
```

补充：

- 精英怪和 Boss 必掉 1 个补给。
- 连续 25–30 秒没有武器掉落时，下一次精英必掉武器。
- 僚机挡弹消耗时，在消耗位置生成一个 1.5 秒可回收“僚机核心”，而不是死亡后掉落。
- 关卡中段给一次 A/B 武器胶囊选择。
- 不复制“死亡后 Option 漂浮回收”。

这样保留沙罗曼蛇的“拾取选择”和“补给路线”，但不叠加死亡惩罚。

## 5. 关卡/Boss 机制优先的改造原则

### 关卡

每关一个主要机制，不靠堆弹幕：

- Stage 1：星云能见度 + 陨石/遮挡 + 基础 Medal
- Stage 2：空间站闸门/激光网格 + 掩体
- Stage 3：地表移动地形 + 风/速度压迫
- Stage 4：圣所旋转激光/十字激光 + 安全区
- Stage 5：时间断裂、阶段视频、融合

原则：

- 机制必须可读、有预警；
- 不增加不可躲的弹幕；
- 关卡机制不能和 Boss 机制同时抢注意力；
- 每关至少有一个“只有这关才有”的记忆点。

### Boss

每个 Boss 一个核心交互，不只是换弹幕：

- B1：分段核心/弱点
- B2：区域控制/吸附/清场
- B3：高速冲撞/装甲破坏
- B4：十字激光/旋转顺序
- B5：多阶段/融合/时间断裂

原则：

- 每个 Boss 至少一个“必须改变走位/输出窗口”的机制；
- 机制不依赖隐藏数值；
- 阶段切换有明确视觉预兆；
- 所有新机制先做安全缺口验证。

## 6. 修订后的开发顺序

### Phase 1：内容审计（3–5 天）

- 5 关现有机制清单
- 5 Boss 现有机制清单
- 重复/缺失/不可读项
- 安全缺口与死亡经济审计

### Phase 2：关卡机制（2 周）

- 每关一个主题机制
- 预警/音效/视觉反馈
- 不新增不可躲区域

### Phase 3：Boss 机制（3 周）

- 每个 Boss 一个核心交互
- 阶段规则/弱点/场地机制
- 安全缺口与平衡

### Phase 4：掉落/死亡经济（1–2 周）

- 数据表掉落
- 必掉/保底
- 僚机核心回收
- A/B 胶囊选择

### Phase 5：Rank / Medal / Score（2 周）

- RunState
- Rank 0–5
- Medal/Chain
- 结算与本地榜

### Phase 6：Boss Rush（2 周，后置）

### Phase 7：Tower（3 周，后置）

### Phase 8：Force / Resonance（可选）

> 注意：Force 与当前僚机都承担“挡弹”角色。  
> 如果做 Force，应作为独立机体替换僚机，而不是叠加第二层盾。

---

## 7. 结论

- Boss Rush / Tower 后置，等 Boss 机制冻结。
- 沙罗曼蛇只借“拾取选择、掉落表、路线”，不借“死亡全清”。
- 当前死亡经济保留，增加保底与僚机回收，不增加死亡惩罚。
- 下一阶段先做 **内容审计 + 关卡/Boss 机制区分**。
