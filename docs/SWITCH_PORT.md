# Nintendo Switch Port — Feasibility and R11 Plan

状态：**可行性评估 / 路线图，未开始移植**  
目标平台：Nintendo Switch（如获资格，可同时评估 Switch 2）  
前置：Steam R10 发行完成，或至少 PC 内容冻结

---

## 1. 结论

**技术上可以做，但不能从当前 Web/Electron 构建直接发布。**

当前游戏是：

```text
HTML5 Canvas 2D
ES5 IIFE 模块
WebAudio
DOM / Electron
```

Switch 没有可用浏览器运行时，也没有 Steamworks。需要：

1. 任天堂开发者资格与 devkit
2. 选择 Unity / Unreal / Godot 等官方支持 Switch 的引擎
3. 重写渲染、输入、音频、视频和平台服务层
4. 通过 Nintendo Lotcheck
5. 重新做 16:9 布局、手柄 UI、存档和线上服务

不是“打包一次”工作量。

---

## 2. 必须先拿到的资格

- Nintendo Developer Portal 账号
- 对应平台的开发许可
- 官方 SDK / devkit
- eShop 发行资格
- 年龄分级、隐私政策、线上服务合规

没有以上资格，不能合法开始正式 Switch 开发和真机测试。  
不使用非官方模拟器或自制固件做验收。

---

## 3. 推荐移植策略

### 方案 A（推荐）：引擎重制外壳

- 保留现有玩法数值、关卡数据和美术资产
- 用 Unity / Unreal / Godot 重建：
  - 渲染层
  - 输入层
  - 音频/视频
  - UI/HUD
- 游戏逻辑按模块迁移，不直接搬 Canvas API

优点：官方支持、Lotcheck 路径成熟。  
缺点：等于一次中等规模重写。

### 方案 B：自研 C++/SDL2

- 最大控制力
- 工作量最高
- 需要自行解决字体、视频、音频、存档、手柄

不推荐作为第一版 Switch 方案。

### 方案 C：WebView/JS 嵌入

- Switch 无通用浏览器/WebView
- 风险极高，不建议作为正式路线

---

## 4. 画面与操作

当前游戏是 **390×844 竖屏**；Switch 是 16:9。

### 推荐布局

```text
左右侧栏 / 装饰边框
中间保留竖屏游戏区
```

先保证：

- 720p 掌机模式稳定 60fps
- 1080p 底座模式稳定 60fps
- HUD 字号在 720p 可读
- 触屏只作为辅助，不强制

### 输入

- Joy-Con / Pro Controller
- 双人本地合作优先
- 菜单全手柄可操作
- 触屏按钮保留但可选
- 不使用键盘/鼠标作为必要输入

这对 R3 的双人同设备设计是正向约束：R3 应优先做手柄优先的本地双人，而不是只做键鼠。

---

## 5. 内容范围

### 首版建议

- Campaign 5 关 5 Boss
- 3 机体 / 9 外观
- 本地双人合作
- 单机存档
- 排行榜可先本地

### 暂不做

- 跨平台联机
- 与 Steam 跨存档
- 成就系统对齐
- Switch 2 专属特性
- 体感/HD 震动作为核心机制

在线联机如果要做，需改用 Nintendo 官方网络服务，不能直接复用 WebRTC 方案。

---

## 6. 里程碑

| 阶段 | 目标 | 预估 |
|---|---|---:|
| S0 | 任天堂资格 / SDK / 引擎选型 | 1–3 个月（审批不可控） |
| S1 | 720p/60 垂直切片：1 关 + 1 Boss + 1 机体 | 2–3 个月 |
| S2 | 三机体 + 本地双人 + 全 UI | 3–4 个月 |
| S3 | 5 关 5 Boss + 性能/内存/加载 | 3–4 个月 |
| S4 | Lotcheck / 分级 / eShop | 2–3 个月 |
| S5 | 发售 / 补丁 | — |

总计：**约 9–15 个月**，取决于团队是否已有 Switch 经验。  
外包给有 Switch 经验的移植团队通常比从零自研快。

---

## 7. 风险

| 风险 | 级别 | 说明 |
|---|---|---|
| 任天堂审批 | 高 | 没有资格就没有正式开发 |
| 引擎重写 | 高 | Canvas 代码不能直接复用 |
| 16:9 改造 | 中 | 竖屏游戏需要新 HUD/侧栏 |
| 性能 | 中 | 弹幕 + 视频背景在掌机模式需压测 |
| 视频解码 | 中 | 背景视频需改为平台支持的格式/解码 |
| 线上服务 | 高 | 不能直接用 WebRTC/Steam |
| 认证 | 高 | Lotcheck 可能要求改 UI/网络/存档 |
| 商业回报 | 高 | 需评估 Switch 用户与移植成本 |

---

## 8. 路线图位置

```text
R10 Steam QA / 发行
R11 Switch 移植（资格 gate）
```

R11 不是 Steam 发行的阻塞项。  
但 **任天堂开发者申请应在 R2/R3 期间尽早启动**，因为审批和 devkit 周期不可控。

Steam Deck 从独立里程碑降为：

```text
R10 内 best-effort Steam Deck Verified
```

不再单独占用一个阶段。

---

## 9. Go / No-Go 门槛

进入 R11 前必须满足：

- [ ] 任天堂开发者资格通过
- [ ] devkit 到位
- [ ] 引擎选型完成
- [ ] 720p/60 垂直切片通过
- [ ] 16:9 布局可读性通过
- [ ] 手柄全流程可操作
- [ ] 移植成本/回收模型确认

任何一项不满足，R11 暂停，不阻塞 Steam 版本。
