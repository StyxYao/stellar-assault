# R3 — Two-Player Co-op (Same Device / LAN / Online)

状态：**规划与架构边界，未实现**  
前置：R2 签收（三机体可玩、教学、设备冒烟）  
目标：双人合作 Campaign，不是 PvP

---

## 1. R3 要做什么

分三个阶段交付，不要求一次做完跨网络：

### R3.0 — 同设备双人

- 同一台设备、同一屏幕
- P1：键盘 / 手柄
- P2：第二手柄 / 键盘分区
- 共享敌人、Boss、弹幕场
- 各自生命、复活、技能
- 共享关卡进度；分数可选共享或分开
- R3.0 当前：P2 镜像 P1 机体/变体，AEGIS/PHANTOM 状态独立

验收：

- 两个玩家都能移动、射击、放技能
- 死亡/复活不互相卡死
- 暂停、设置、结算不破
- 单机模式不受影响

### R3.1 — 局域网双设备

- Host / Join
- 房间码或局域网 IP
- 两台设备，同局域网
- Host 权威模拟，客户端输入上行
- 目标延迟：同 LAN < 40ms

验收：

- 两台设备可创建/加入
- 敌人、Boss、弹幕一致
- 断线可回到菜单，不冻结
- 不要求公网穿透

### R3.2 — 不同网络在线

- 房间码加入
- Signaling + STUN/TURN 或轻量 relay
- Host 权威，客户端预测/插值
- 目标延迟：80–150ms 可玩
- 不要求专用服务器、匹配大厅、排位

验收：

- 不同网络可完成第一关
- 200ms 内不出现不可恢复的不同步
- 掉线/重连有明确状态
- 不把在线延迟转成不可躲弹幕

---

## 2. 不做

- PvP
- 4 人
- 专用服务器舰队
- 全自动匹配 / 天梯
- 跨平台联机
- 观战 / 回放分享
- 主机迁移（R3 先不做）

---

## 3. 技术前置

当前障碍：

- `player`、`enemies`、`boss`、`bullets` 是闭包全局
- 单玩家假设贯穿 HUD、输入、存档、结算
- 只有固定步，没有输入帧 / 状态快照 / 确定性 RNG
- 没有网络层、没有房间生命周期

必须先做：

1. `World`：实体容器与更新顺序
2. `PlayerSlot`：P1/P2 输入、生命、技能、分数
3. 输入帧协议：`tick, playerId, move, fire, skill`
4. 固定 60Hz 模拟 + 状态快照
5. 确定性种子 + 可复现测试
6. Host 权威同步；客户端只发输入，不直接改世界

建议网络：

- LAN/在线统一 WebRTC DataChannel
- 在线增加 signaling + TURN
- 状态同步 10–15Hz + 客户端插值
- 弹幕数量大时只同步生成事件，不同步每颗子弹位置

---

## 4. 与现有系统的关系

- 存档：R3 只保存单机进度；联机成绩单独标记，暂不写主榜
- 排行榜：R3 不做联机榜，R7 再统一
- 机体：三机体都可选；双人可重复机体
- 平衡：双人敌人 HP/弹幕需要单独倍率，不能直接沿用单人
- 暂停：联机暂停需要双方确认或只允许 Host 暂停
- 死亡：各自生命；是否允许队友复活，R3.0 先不做

---

## 5. 风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 全局状态重构 | 高 | 先 R3.0 本地双人，强制拆 World |
| 弹幕同步量 | 高 | 同步生成事件 + 种子，不同步逐弹 |
| 不同网络 NAT | 高 | TURN/relay 预算；R3.2 才承诺 |
| 双人平衡 | 中 | 敌人 HP/弹幕倍率单独测试 |
| 联机存档/榜单 | 中 | R3 不写主榜，避免污染 |
| 工期 | 高 | 分 R3.0/1/2 三次可停 |

---

## 6. R3 验收总门槛

- 同设备双人第一关可完成
- 局域网双设备第一关可完成
- 不同网络第一关可完成
- 单人模式回归通过
- 三种输入（键鼠/手柄/触屏）不互相破坏
- 无软锁、无不可恢复不同步
- R2 的三机体平衡不被联机倍率破坏

> R3 是“双人合作基础”，不是完整在线游戏。R4 起才回到内容审计和关卡/Boss 机制。
