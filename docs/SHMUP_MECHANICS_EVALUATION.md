# 战机机制学习清单 — 系统评估与开发取舍

版本：v1.0  
对照基线：`172abdc`（Steam M2）  
输入材料：《战机类经典游戏机制学习清单》v1.0（马库斯，2026-10-24）

---

## 1. 对清单本身的评价

### 做得好的地方

- 把五款作品拆成五个**互不重叠的机制原型**，而不是简单列游戏。
- 明确说明官方游戏逻辑源码不公开，把 MAME 驱动定位为“硬件边界资料”，这个区分是对的。
- 把 L1 硬件源码、L2 反汇编、L3 开源复刻分层，学习路径清晰。
- 强调“抄什么 / 别抄什么”，没有把经典设计全部神圣化。
- 对死亡惩罚、操作认知负荷、街机投币经济的分析，比单纯讲弹幕设计更有价值。

### 需要修正或降级为“待实测”的部分

| 清单说法 | 处理 |
|---|---|
| 斑鸠最多 5 发追踪激光 | 不同版本/资料存在差异，代码设计不要写死 5；参考维基为最多 12 级、每级 1 发 |
| 斑鸠“最高 128 链” | 混淆了 chain 数与最高 25,600 倍率；不要拿这个数字做数值设计 |
| 彩京 Rank 的三因子公式 `0.4/0.4/0.2` | 这是设计启发式，不是原作真实公式；只能作为我们自己的初始模型 |
| 彩京 Rank 只调速度 | 部分作品高 Rank 会改变 pattern 选择；我们的实现应先只调速度/冷却，避免不可躲 |
| R-Type 三色激光 | 不同代际映射不同；不要照抄攻略，先做机制抽象 |
| 哞哩的怒气/雪貂/升级树细节 | Steam 页只确认了弹药技能、道具、大招、Boss；具体槽位与召唤兽规则需实机验证 |
| MAME 源码 = 游戏逻辑 | 不成立；MAME 只提供硬件驱动，游戏逻辑仍在 ROM 机器码里 |
| L3 复刻代码可直接商用 | 不成立；只能学习机制，代码许可证/ROM 风险必须单独审查 |

### 一句话结论

这份清单适合当**机制词典**，不适合当**数值规格书**。  
我们必须自己定义数值、反馈、失败惩罚和内容节奏。

评分：5 高，1 低。  
“成本”越高越贵。

| 机制 | 玩法价值 | 与现有系统重合 | 工程成本 | 平衡风险 | 内容复用 | 建议 |
|---|---:|---:|---:|---:|---:|---|

## 3. 逐项判断

### 3.1 斑鸠极性：不要做全游戏底层

**清单正确的地方**

- 同色吸收、异色双倍伤害、同色连锁，是“一键多义”的教科书设计。
- 吸收要有强反馈、短暂冻结、视觉过渡。

**不适合我们的原因**

- 当前所有弹幕、Boss pattern、颜色语义和美术都按“躲避”设计。
- 全量增加 polarity 字段会重写碰撞、伤害、掉落、HUD、Boss 和教学。
- 触屏玩家只有一根手指移动，再增加切换键会挤压操作带宽。
- 我们的弹幕已经有大量颜色，如果颜色既表示“危险”又表示“资源”，可读性会崩。

**建议**

- 不做 Campaign 基础规则。
- 做一架**独立解锁机体** `RESONANCE`：
  - 同色吸收
  - 异色双倍伤害
  - 吸收转追踪激光
  - 单独排行榜
- 作为 1.1 或挑战模式内容，而不是 1.0 主线。

### 3.2 R-Type Force：最值得吸收的“实体化火力”

**清单正确的地方**

- Force 把防御、火力、走位耦合在一个实体上。
- 挂载/发射/回收的状态机清晰。
- 发射 = 放弃防御换输出，是明确的风险交换。

**与我们的关系**

- 我们已经有僚机/Options，但它们是纯自动火力，没有位置决策。
- 可以把僚机升级为可分离 Force，而不是新增一套完全独立的系统。

**建议**

- 1.0 先做一架 `FORCE` 机体或一个 Force 模块：
  - 默认前置挂载
  - 按键分离/回收
  - 分离时挡弹但主武器降级
  - 蓄力炮三级
- 不做“死亡全丢”，改为死亡后 Force 短暂漂浮可回收。
- 这是 1.0 唯一值得新增的“重机制”；如果排期紧，后置 1.1。

### 3.3 沙罗曼蛇拾取：低成本、高复用

**清单正确的地方**

- 数据表驱动拾取物，别为每种写一个类。
- Option 用历史轨迹采样，不用弹簧跟随。
- 死亡惩罚是难度旋钮。

**与我们的关系**

- 我们已经有权重掉落、武器切换、僚机、炸弹。
- 缺的是“拾取选择”和“死亡后的缓冲”。

**建议**

- 1.0 做三件小事：
  1. 掉落表数据化：`P/A/W/B/SHIELD` 权重与条件
  2. 死亡后僚机短暂漂浮 2 秒，可回收
  3. 关卡中一次 A/B 武器胶囊选择，而不是只靠随机掉落
- 不做双人同屏。
- A/B 关卡路线放到 1.1。

### 3.4 彩京 Rank：1.0 最高性价比

**清单正确的地方**

- Rank 应主要调速度/频率，不要突然改 pattern。
- 炸弹必须是即时清屏 + 短无敌，否则玩家不敢用。
- 机体差异应该改变玩法，不只是数值。

**需要修正**

- 原作 Rank 公式不可考；我们的公式必须自己设计并实测。
- Rank 不能直接把弹幕变成不可躲；我们有安全缺口/预警圈，Rank 只能影响速度和冷却。

**建议模型**

```text
rankScore =
  0.30 * 无伤推进
+ 0.25 * 当前火力等级
+ 0.20 * 连续 Medal
+ 0.15 * 快速击杀
- 0.40 * 死亡
- 0.20 * 撞机
```

- Rank 0–5，HUD 可见。
- 只影响：
  - 敌弹速度
  - 敌弹发射冷却
  - Boss 攻击间隔
- 不直接增加同屏弹数，不修改缺口宽度。
- 死亡降 1–2 级，连续无伤缓慢回升。
- 高 Rank 提高分数倍率，形成风险回报。

**蓄力**

- 不放进基础机体，避免和自动射击冲突。
- 放进 `FORCE` 机体或 `CHARGE` 模块。
- 三级蓄力要有弹体、音效、震动三级反馈。

### 3.5 哞哩长梦：用于 Tower，不用于 Campaign

**清单正确的地方**

- 用成长曲线降低门槛。
- 用怒气/超级状态制造情绪节奏。
- 伙伴/召唤物降低单机孤独感。
- 用主题关卡和 Boss 记忆点弥补体量。

**与我们的关系**

- 我们已有 OD、武器升级、僚机、Boss 演出，重复做“怒气”会冗余。
- 真正缺的是**局内构筑选择**和**关卡主题记忆点**。

**建议**

- 不新增 Campaign 怒气条；OD 已经承担这个角色。
- 在 Tower 中做：
  - 每 5 波三选一升级
  - 击杀/无伤获得“Resonance”货币，用于刷新选项
  - 召唤兽作为可选升级，不做常驻
- Campaign 只吸收两点：
  - 每关一个明确机制主题
  - Boss 前收集/大招节奏

## 4. 我们当前真正缺什么

按重要性：

1. **计分深度**：现在只有击杀/命中分，没有 chain、medal、rank 倍率。
2. **模式结构**：Campaign 之外的 Boss Rush/Tower 只有契约，没有 run state。
3. **机体差异**：现在所有玩家用同一机体，只有武器切换。
4. **局内构筑**：没有三选一、路线、风险选择。
5. **排行榜可信度**：本地最高分有了，但没有 run result、wave、seed、validation。
6. **Boss 个体机制**：Boss 数量和演出不少，但缺少“必须改变打法”的机制型 Boss。

## 5. 建议的 1.0 / 1.1 范围

### 1.0 首发

```text
Campaign（5 关）
Boss Rush（5 Boss）
Tower Lite（30 波，每 5 波 Boss）
Rank 0–5
Medal / Chain
2 架机体：VECTOR + FORCE
沙罗曼蛇式掉落表 + 死亡僚机回收
本地排行榜
Steam 成就 / 云存档
```

### 1.1 后置

```text
RESONANCE 极性机体
Campaign A/B 路线
Tower 每日种子 / 更多升级
第三个机体
Steam 全球排行榜
```

### 不建议 1.0 做

- 全游戏 polarity 底层
- 双人同屏
- 六个机体
- 永久 meta 成长/装备词条
- 关卡编辑器
- 二周目强制循环

## 6. 开发路线

### Sprint A：Score / Rank / Medal（2 周）

- `RunState`：score、rank、medal、chain、deaths、time
- Rank 状态机与 HUD
- Medal 掉落/倍率
- 结算页
- 本地排行榜
- 存档扩展

验收：

- 无伤升 Rank，死亡降 Rank
- Rank 只改速度/冷却，不破坏缺口
- Medal 3 级倍率
- 分数可保存/读取

### Sprint B：Boss Rush（2 周）

- `GameModeRuntime`
- Boss 序列
- Boss 间整备
- 结算与榜
- 解锁条件

验收：

- 5 Boss 可连续通关
- 死亡/通关都写榜
- 无软锁

### Sprint C：Tower Lite（3 周）

- 波次模板 + 种子
- 每 5 波 Boss
- 每 5 波三选一
- Rank
- 死亡结算
- 本地榜

验收：

- 30 波可完成
- 同种子可复现
- 无不可击杀组合
- 榜单记录 wave/score/seed

### Sprint D：FORCE 机体（2 周）

- 挂载/发射/回收状态机
- 挡弹、接触伤害
- 三级蓄力
- 机体选择 UI
- 平衡

验收：

- Force 机体与 VECTOR 玩法不同
- 键鼠/手柄/触屏都能操作
- 没有单一最优机体

### Sprint E：Campaign 打磨（2 周）

- 每关主题机制
- 掉落表/死亡回收
- Boss 个体机制
- 难度曲线

### Sprint F：RESONANCE（可选，2–3 周）

- 极性吸收
- 双倍伤害
- 追踪激光
- 独立榜

### Sprint G：QA / Steam（2 周）

- 全模式平衡
- Steam 排行榜/成就
- Deck/Windows
- 商店素材

总工期：

```text
1.0：约 11–13 周全职
1.1：再加 6–10 周
```

## 7. 最终建议

只保留两个主要学习方向：

1. **彩京**：Rank、Medal、速度感、机体选择 → 1.0 核心
2. **R-Type**：Force 实体化火力 → 1.0 唯一新增重机制

其他采用“低剂量”：

- 斑鸠：只做 1.1 特殊机体，不改基础规则
- 沙罗曼蛇：掉落表、死亡回收、A/B 路线
- 哞哩：Tower 三选一、关卡主题、Boss 记忆点

不要为了“像经典”而同时加入极性 + Force + 蓄力 + 怒气 + 双人。  
我们的优势是**割草节奏、Boss 演出、可视化安全缺口和移动端可玩性**，不是复刻街机硬核。
